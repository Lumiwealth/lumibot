## Executive Findings

- SQLite and Parquet match for all three runs. The live `memory.sqlite` store exported `memory_events`, `memory_retrievals`, and `memory_state` Parquet artifacts correctly.
- Memory state injection worked on every agent call summary row in all three runs: 132/132 rows per run had non-empty `memory_state_text`.
- Retrieval provenance worked at the run level: every `memory_retrieval_ids` value in `stats_agent_detail.parquet` matched a row in `*_memory_retrievals.parquet`.
- The biggest gap is attribution: `agent_name`, `model_call_id`, and `retrieval_id` are null in the memory event/retrieval Parquet rows. The agent detail file can still identify which agent called the memory tools, but the memory artifacts themselves do not carry that provenance yet.
- Memory content quality is mixed. It captured useful theses and retrievals, but non-trading agents can write decision memories that may not match executed orders. Run 1 records a `900` share SOXL decision while the trader actually bought `1,860` shares.
- Memory did not cause the initial SOXL convergence. The first SOXL selection happened before history existed. Memory mainly helped later hold/rotate explanations and made the run auditable.

## Detailed Assessment

### What worked

- Durable memory storage worked: SQLite persisted and Parquet exports matched the SQLite row counts.
- Memory injection worked: every agent call had a compact memory state section, so the model always had access to the current open thesis/projection.
- Retrieval records worked: search calls produced rows with query text, selected IDs, and rendered snippets.
- Memory affected run 3 in a visible way: the agent retrieved prior SOXL/LABU thesis context around the 2026-05-11 and 2026-05-12 rotation.

### What did not work well enough

- Memory provenance is incomplete inside the memory artifacts. `agent_name`, `model_call_id`, and `retrieval_id` are null in memory events/retrievals. Agent detail can reconstruct tool caller attribution, but the memory Parquet files should carry it directly.
- The meaning of `remember_decision` is too loose. In run 1, a read-only bull agent recorded a 900-share SOXL decision, while the trader actually bought 1,860 shares. That creates an inaccurate memory record.
- Run-to-run memory behavior is inconsistent. Run 1 updated the SOXL thesis nearly every day. Run 2 opened a thesis and then barely updated memory. Run 3 aggressively wrote lessons and retrievals. The system works, but model compliance varies a lot.
- Search quality is basic lexical matching. It found relevant SOXL/LABU items, but there is no ranking explanation beyond selected IDs/rendered text.
- Memory state has no explicit outcome validation loop yet. Lessons are mostly `proposed`, not later validated or rejected against actual returns/drawdowns.

### Code-path cause of missing attribution

The SQLite schema and `MemoryStore` methods already support provenance fields:
`agent_name`, `model_call_id`, and `retrieval_id`. The missing piece is the
agent tool binding layer. The memory tools in
`lumibot/components/agents/builtins.py` call methods like
`strategy.memory.search(...)`, `strategy.memory.remember_decision(...)`,
`strategy.memory.open_thesis(...)`, and `strategy.memory.update_thesis(...)`
without passing the active agent name or model call ID. That is why the Parquet
artifacts have correct rows but empty attribution columns.

The agent detail artifact can still reconstruct memory-tool caller attribution
because it records the tool call rows by `agent_name`. That is a workaround, not
the desired final contract. The memory artifacts should be self-describing.

### Recommended fixes

1. Stamp every memory event and retrieval with `agent_name`, `model_call_id`, and ideally `call_index` from the active agent run.
2. Split memory write semantics: `remember_decision` should mean actual executed strategy decision, while non-trading agents should write `proposal`, `risk_note`, or `thesis_note`.
3. Automatically record executed orders into memory from Lumibot itself, so memory always has a mechanical source-of-truth record for actual trades.
4. Add a daily outcome update step for open theses: unrealized return, drawdown since entry, whether thesis remains valid, and what would invalidate it.
5. Add tests that assert memory events exported to Parquet include attribution and that an executed order creates a matching factual memory event.

## Remediation Implemented

Implemented on 2026-05-26 after this audit:

1. Agent memory tools now receive active `agent_name` and `model_call_id` context from the runtime. Memory events and retrievals written by agent tools carry those fields directly in SQLite and Parquet.
2. `remember_decision` is now treated as an actual trading decision write and is removed when `allow_trading=False`. Read-only agents can use `remember_proposal` and `remember_risk_note` instead.
3. `orders_submit_order` records an append-only `order.submitted` memory event after Lumibot submits the order.
4. Open theses receive a best-effort once-per-day `thesis.outcome_observed` event while the thesis symbol is held, including quantity, last price when available, and market value when available.
5. Targeted tests cover provenance export, read-only tool permissions, proposal/risk-note writes, automatic order events, and once-per-day thesis outcome observations.

Still not solved in this pass: semantic/vector retrieval and automated validation or rejection of lessons against realized returns. The new outcome observations provide the factual trail needed for that next layer, but they do not yet decide whether a lesson is proven.
